断点调试：从暂停到找到原因

下面两个例子都能在练习网页中直接运行。先打开左侧 debug 文件夹，再选择对应的 Python 文件。第一次启动会加载 Python，请等下方“调试控制台”显示“Python 已就绪”。

设置断点找到调试按钮循环边界函数参数调用堆栈修改与验证

1. 断点让程序停在你关心的地方

断点是给程序设置的暂停位置。程序运行到这一行时，会在执行这一行之前停下来，方便我们查看变量、逐步执行。

  1. 打开 01_循环边界.py

    找到第 7 行 total = total + i。

  2. 单击行号左侧的空白处

    出现红点，表示断点已经设好。再点一次可以取消。也可以先把光标放到这一行，再按 F9。

  3. 按 F5 启动，再按 F5 继续到断点

    本网页默认会先停在第一条可执行语句。此时再按一次 F5，才会运行到刚设的断点。黄色高亮行是下一条要执行的代码，不是已经执行完的代码。

n = 5 是这次调用传入的参数值：主程序把 number = 5 传给 sum_to(number)，因此函数内的 n 等于 5。编辑器若在代码右侧显示灰底的 n = 5，那是调试器的提示，不需要输入到源码里。

2. 调试按钮在编辑区上方

启动调试后，上方会出现一条浮动工具栏。将鼠标停在图标上可以看到操作名称。下面列出本练习网页的快捷键。

F5 · 继续
继续运行，直到遇到下一个断点、异常或程序结束。
F10 · 单步跳过
执行当前语句。遇到函数调用时，把整个函数作为一步执行，然后停在下一条语句。
Alt + F11 · 进入
进入自己写的函数，观察函数内部的执行。网页用 Alt + F11，避免 F11 被浏览器用作全屏；桌面 VSCode 通常用 F11。
Shift + F11 · 跳出
执行完当前函数，回到调用它的位置。它不会修改代码，也不会自动修复错误。
Shift + F5 · 停止
结束本次运行。改完代码后重新按 F5，让新代码从头执行。

如果笔记本把 F5、F10 用作亮度或音量键，试着同时按住 Fn，或者直接点击工具栏里的同名按钮。

3. 循环边界：为什么少加了 5？

这个函数要计算 1 + 2 + 3 + 4 + 5，预期是 15，原程序却得到 10。断点停在加法这一行时，先看左侧“变量”：n = 5、i = 1、total = 0。

  1. 按一次 F10，执行 total = total + i。此时 total 从 0 变成 1。
  2. 继续按 F10。程序在循环头和加法之间往返，i 依次取 2、3、4。
  3. 到 return total 时，i 最后停在 4，total 为 10。全过程没有一次 i 等于 5。
原因与修改

range(1, n) 包含起点 1，不包含终点 n。因此需要把终点改成 n + 1。

for i in range(1, n + 1):
    total = total + i

先停止调试，再修改、重新运行。原来的输入仍用 number = 5，控制台应输出“计算结果：15”。

4. 函数参数：优惠券为什么反而减出了负数？

打开 03_函数参数.py。买 3 本书，每本 12 元，使用 5 元优惠券，应付 12 × 3 − 5 = 31 元。

  1. 在调用处暂停

    给第 11 行 result = pay_after_coupon(coupon, subtotal) 设置断点。按 F5 启动，再按 F5 运行到断点。此时 subtotal = 36、coupon = 5。

  2. 单步进入函数

    按 Alt + F11。进入 pay_after_coupon(total, coupon) 后，左侧变量变成 total = 5、coupon = 36。参数按位置对应：第一个值给 total，第二个值给 coupon。

  3. 执行减法，观察返回值

    按 F10 执行 payment = total - coupon，得到 payment = -31。函数本身按“总价 − 优惠金额”计算，错误来自调用时把两个参数放反了。

5. 调用堆栈：这个函数是谁调用的？

左侧“调用堆栈”记录当前还没有执行完的调用。最上面是当前函数，往下是调用它的上一层。点击某一层，可以查看那一层的源码和局部变量；查看其他层不会让程序倒着执行。

  1. pay_after_coupon：当前正在计算实付金额的函数。
  2. checkout：上一层调用者，在第 11 行调用了 pay_after_coupon。
  3. <module>：最外层主程序，在第 15 行调用 checkout(12, 3, 5)。

按 Shift + F11 会执行完当前函数并返回调用处，便于继续观察。这个动作只是控制执行过程；要修正参数，仍然需要停止后编辑源码。

6. 停止、修改，再用原输入验证

按 Shift + F5 停止。打开 checkout 中的调用，把总价 subtotal 放前面，优惠金额 coupon 放后面。

修改前
pay_after_coupon(coupon, subtotal)
                 ↓        ↓
              total=5  coupon=36
修改后
pay_after_coupon(subtotal, coupon)
                 ↓        ↓
              total=36  coupon=5
result = pay_after_coupon(subtotal, coupon)

重新按 F5 启动，保持原来的输入 checkout(12, 3, 5)。继续运行后，调试控制台应输出“应付金额：31”，最后的 assert 检查也应通过。只有重新启动，才会执行修改后的代码。

还可以继续探索什么？

这节课只介绍了调试的冰山一角。熟悉暂停、观察和单步之后，还可以尝试：

  • 条件断点：右键红点，编辑条件，例如 i == 4，只在指定一轮暂停。
  • 监视表达式：在左侧“监视”里点 +，输入 n - i，每次暂停时查看还差多少。
  • 异常断点：打开 05_越界异常.py，让调试器在访问越界的位置暂停，检查索引和列表长度。
